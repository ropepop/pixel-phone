# Pixel artifact policy migration

Source acceptance pending the root's coherent maintenance/artifact/encoder
checkpoint. The actual phone still runs the accepted decoder predecessor.

## Active owner and boundary

`ArtifactSyncer` now delegates SHA-256 normalization, existing-cache admission,
absolute local-source restriction, streaming SHA-256 and private-cache release
admission to `pixel-health::artifact`. Java keeps normalized Path semantics,
Files copy/delete and the existing permission-denied RootExecutor fallback.
The JNI error boundary preserves NoSuchFileException and AccessDeniedException;
no artifact contents are returned or logged.

The active Facade bootstrap/component manifest validators and RuntimeInstaller
required-artifact validation, component release validation and DNS ordering now
call `ArtifactAdmission` in the same native owner. Required/optional ID lists
remain input configuration; native policy owns first-match choice, required flag,
local URL restriction, duplicate/order behavior and failure precedence. Kotlin
preserves the original IllegalStateException versus IllegalArgumentException.
The unused JCA RuntimeManifestVerifier is not an active caller and was unchanged.

`sha2 = 0.10.9` is pinned; its transitive lock entries were added without changing
existing dependency versions. Copy/unpack/permission and root-process effects
retain their canonical call sites. Retired bot component release/pruning paths
are not active phone services.

## Source and test proof

Frozen actual `dd41627` ArtifactSyncer compared real files, native-versus-JCA
checksums, target replacement, rejection, exact exception classes/messages,
file bytes/permissions and cache release boundary in 57 cases. The prior Facade
and RuntimeInstaller manifest validation functions are extracted from that Git
source by the fixture, with 81,944 complete comparisons of result, failure class,
message and precedence. Includes Unicode blank input, case variation, missing
required entries, duplicate IDs, optional required flags, local versus remote
URLs, signature/schema/target/release failures and DNS ordering.

`run-artifact-parity.sh` passes with all existing runtime-installer tests.
Exact outputs are preserved under `output/rust-migration/` rather than relying
on Gradle XML surviving a later build. The disposable Android app-cache fixture
checks the installed library's checksum, real replacement/deletion behavior and
both active manifest entry points. Device acceptance remains pending its actual
execution and final release identity.

## Actual device performance check

The first actual Pixel `app_process` probe found correct hashes but a software
SHA regression: native/previous-Java time ratios 3.28 at 64 KiB, 5.81 at 1 MiB
and 5.30 at 8 MiB, each six alternating warm runs. The same pinned sha2 0.10.9
dependency now enables its existing asm feature. NDK CC/AR environment is passed
explicitly for its assembly dependency. Repeating the identical actual phone
probe gave ratios 0.43, 0.83 and 0.87; digest equality passed every run.
Software library SHA-256 `c2319cfc770be73bf06b7c60b6a6910d2b4cb916a90ab388a94422010b1eaf48`;
hardware-enabled library `9291e1bba3bcabaf30c306b43d08483d47a51848d3a3ea95e09b1b0297841de7`.
Logs and the former library are saved under output/rust-migration. The probe used
generated bytes only, and its owned phone directory was removed and verified
absent. This proves real ARM JNI checksum behavior; installed-product fixture
timings will also be checked separately after the final APK install.
